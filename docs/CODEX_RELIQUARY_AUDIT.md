# SERVATI Codex Reliquary Archive Audit

## Scope

This audit covers the Quartz presentation layer generated by
`codex/build_servati_content.py`. It does not revise SERVATI setting text or
change the authority boundary between Version 11 canon and Version 12 draft
material.

## Findings addressed

1. Title-only portal and related-entry wikilinks produced broken or ambiguous
   destinations. Generated links now carry explicit vault paths.
2. Every generated file injected a body H1 in addition to Quartz Article Title.
   Article Title is now the sole page H1; imported top-level sections are
   normalized to H2. Extracted chapters and draft entries stop at the next
   same-level or higher-level source boundary.
3. Unmaterialized draft-only future hooks appeared as dead links. Unique known
   destinations are resolved explicitly; unresolved or ambiguous hooks remain
   readable text rather than false navigation. Duplicate controlled terms are
   not assigned an arbitrary category destination.
4. Recent Notes reflected build filesystem time. Generated pages now use the
   last source commit date in frontmatter.
5. Virtual folder pages exposed raw slugs and empty descriptions. Seven authored
   archive indexes now provide controlled titles, descriptions, and listings.
6. The homepage lacked usable information hierarchy. It now presents status,
   five counted registers, featured records, and direct library actions.
7. The original mobile layout overflowed and obscured archive tools. The final
   layout uses a single-row mobile command bar and a one-column content grid.

## Visual system

The page uses a graphite and charcoal field, bone text, oxidized-metal rules,
restrained amber links, mineral cyan navigation signals, verified green, draft
amber, and breach red. Borders are square, spacing is compact, and cards are
limited to the homepage's explicit register grouping.

Desktop retains the Quartz three-column model: archive registers on the left,
the record in the center, and local context on the right. Tablet moves context
below the record. Mobile keeps Search, theme control, and Explorer in a compact
command bar and collapses all record groups to one column.

## Verification baseline

Recorded on 2026-09-08, the local build reproduces the workflow's pinned Quartz
revision and plugin configuration with Node 24. Generation uses
`python codex/build_servati_content.py`; the artifact is checked with
`python codex/verify_servati_site.py` using the workflow's verified plugin
result:

- 235 generated Markdown pages
- 235 represented source pages
- 254 emitted HTML pages
- 297 files in the checked artifact inventory
- zero generated body-level H1 headings
- zero unresolved title-only generated wikilinks
- zero built links carrying Quartz's `broken` class
- successful HTTP checks for the homepage, representative chapter, lineage,
  environment, search index, stylesheets, and scripts
- desktop, article, and 390px mobile browser captures inspected

Exact plugin source-link verification remains enforced by the Linux GitHub
Actions workflow. The Windows local plugin installer uses junction semantics
that do not satisfy the verifier's symlink identity check, so the local visual
build does not replace that CI trust check.
